# 范围与全季审核

用于连续多集或整季检查。先运行 next/index，读取指定范围的正文、实际连续性、大纲和现有问题。工具查到的冲突是候选问题，仍需核对正文；没有结构化记录时直接审读原文，并标明机器检查未覆盖。

## 六个维度与诊断方法

- 人物弧线：逐集列出关键选择、付出代价与关系结果，检查结尾选择是否有此前行为支持。人物“说自己变了”不是完成弧线的证据。
- 冲突升级：比较各集目标、阻力、损失与选择。若只增加威胁台词却没有新代价，建议改变行动条件，而非机械加反转。
- 重复节拍：将每集压成“试图做什么→受阻→采取什么不同选择→什么变了”。相邻集仅更换人物名而因果不变，是重复候选；有意重复必须提供新的信息或情感意义。
- 信息释放：分别追踪观众和角色知道什么，回查获得信息的场次。看到证据的一部分不等于知道全部真相；故意说谎与作者泄露信息分开判断。
- 伏笔兑现：对照计划与实际，区分尚未到期、延后有记录、取消有原因、遗漏。回收必须改变理解或行动，不能只重复道具特写。
- 结局铺垫：从结局解决方式倒查已建立的能力、关系和规则，标出突然出现的解围条件；开放结局仍需兑现本季承诺。

每个问题给正文版本、集场/对白定位、原文证据、矛盾关系、最小修改建议和受影响范围。只审核时不改正文；自审明确标为作者自审，不冒称独立评审。

## 写作与修订示例

**节拍**：连续两集“被怀疑→否认→留下悬念”缺少进展。可让第二集的否认必须付出交出证据的代价；核查第三集是否继承失去证据后的限制。不要只在结尾再加一个陌生电话。

**对白**：人物对同事说“我们在这里工作了十年”通常只为观众解释。若当场目的为阻止对方丢弃旧账本，可改为“十年的账，你现在说烧就烧？”；保留或修改事实由原文和本次授权决定，示例不应机械套入所有人物。

**知情**：EP001 仅看到纸片吻合，EP002 就说“你昨晚偷了整页”属于证据不足的断言候选。可以改成试探，也可能由表演明确为虚张声势；不能直接补记“角色已知道偷窃者”。

**修订**：先列不变量（故事结果、已确认事实、硬预算），选择最小改动，再复核受影响台词、连续性和交接。解释型补丁可能增加时长或泄露悬念，不能只关闭原问题。

## 报告契约

范围报告保存在 reviews/ 下，正文保留逐项证据，另附唯一 review-json 块：

```review-json
{"episodes":["EP001"],"method":"作者自审；实际已读范围见报告", "dimensions":{"character_arc":{"status":"unverified","evidence":"尚未读到人物结局"},"escalation":{"status":"pass","evidence":"EP001-SC001 隔门收物后转为试探来源"},"repetition":{"status":"unverified","evidence":"单集无法比较跨集重复"},"information":{"status":"pass","evidence":"仅确认纸片关联，没有断言来访者是偷窃者"},"foreshadows":{"status":"unverified","evidence":"后集尚未完成"},"ending":{"status":"unverified","evidence":"全季结局未审"}}}
```

status 为 pass/revise/unverified，全部六维必填；未验证项说明缺失。运行 `review-check PROJECT --file reviews/season.md`；只有覆盖全部已登记集才能 register --kind season_review --scope project。reviewed/locked 要求六维均 pass，且所有正文/连续性有效。范围报告不是全季批准，正文真实阅读仍由审稿者负责。
