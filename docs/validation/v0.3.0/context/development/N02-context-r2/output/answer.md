## 当前冲突

**Q001／P0：EP012 把故障当正常验收。** bible.md 新设定逐字为：“钟正常时只响一声；响两声属于故障。” episodes/EP012-v1.0.md，EP012-SC001-B001 原文：“钟响两声后商宁松手，杜衡数完余音。” EP012-D001 原文：“该响的两声都到了，明早再试一次。” 两声事件本身可以保留为故障；真正冲突是“该响的”将故障解释为预期结果，随后只约定复测，没有识别故障的行动或对白。不能仅换数字或仅改台账掩盖这一因果缺口。

**Q002／P0：旧依赖与检查点不能承载新规则。** bible 登记哈希前缀 cb51eb98，现文件为 93517e89；实际逐文件比对，只有 bible 字节变更。outline、EP001–EP012 正文及台账仍沿旧依赖链，因此待复核；context 的 changed_since_checkpoint 列表不等于这些文件正文都被改过。EP012 审核也依赖旧正文和台账。CP1 留有 draft、空证据，issues 为空不表示无问题；reviews/EP012-v1.0.md 更明确写着：“未完成语义审核，未批准制作。”

**Q003／P1：实际状态记录不足。** EP001–EP011 台账的 states 均为空，无法替代正文回读。EP012 台账仅记钥匙与待复测，漏掉新规则下的两声故障事实及人物是否识别故障。钥匙没有发现冲突：EP006-SC001-B001 为“杜衡把工具箱钥匙交给商宁，商宁挂到腰间。” EP009-SC001-B003 为“杜衡装好垫圈，商宁关箱后仍把钥匙挂在腰间。” EP012-SC001-B003 为“商宁拍了拍腰间钥匙，把待复测纸条贴到钟罩上。” 但 EP012-D002“箱子先锁好，钥匙还在你腰上。”只是锁箱指令；没有上锁动作，不能记成已锁。

时间按场头“时间：内景/日”，不能因剧名“夜钟”判成夜间；“明早再试一次”仍是未来计划。EP001-D001“八点只响了一声。”在新规则下不再单独证明故障；应复核检修动机，但 EP002 已有松动铜锤，不能据此断言前十一集全部无效。EP008-D001“一声，等它停。”可与新规则相容。
