# 0.2.0 补充验收方案

制定日期：2026-10-25。此前的“43 项测试通过”只证明确定性规则；本轮补充实质性返工与独立 Skill 执行。目标保持原 0.2.0 边界，不把真实配音、外部接收或任意 Markdown 理解追加为发布前提。

## 预先固定的通过标准

| 里程碑 | 本轮补充证据 | 通过标准 |
| --- | --- | --- |
| M1 | 独立执行者仅依据文档，在临时副本做初始化/追加、检查点与恢复 | 不修改注册表绕过检查；能找到缺失/过期输入与下一步；记录命令和结果 |
| M2 | 六个新题材案例，由独立案例作者生成原文与单独 oracle；两次不共享结论的 Skill 执行 | 每轮发现全部预置重大矛盾；三个正常对照无重大误报；oracle 必需事实均有证据、无禁止推断；保留原始输出并逐条评分 |
| M3 | 将“林夏预知登记内容”改成“此前从未见过登记页”，真实改写三集关联剧情 | 旧版/旧包保留；新因果和知情有证据；失效传播正确；按依赖真实复核；关联问题闭环；独立复核不留 P0/P1 |
| M4 | 可读 Markdown 场次/对白表直接提取，不要求内嵌 JSON；来源/场次/角色/对白核对 | 正常匹配；漏句、错说话者、旧来源、重复/冲突格式均不可 MATCH；未知格式 UNVERIFIED；JSON 兼容保留；录入实测功能按原需求验证来源与数值，实际测音频不属于本版 |
| M5 | 官方技能校验、全套回归、旧项目兼容、独立文档复跑、证据索引 | 37 个 Skill 官方校验通过；全部确定性测试通过；上述所有验收结果可回查；无伪造独立/真人审稿或真实接收 |

语义样本是有界验收集，不据此推断生产总体准确率。两次评测均由 AI 执行，父执行者对照 oracle 评分，不冒称真人判断。未经评分不能预填“全部通过”。如果出现漏检/误报，保留失败结果，修复后重新运行，不能删除不利样本。

## 隔离与顺序

- fixtures/ 只放 request.md 与 source.md；oracle.json 独立保存。评测执行者只获技能、请求和原文路径，不给 oracle 或预期结论。
- runs/round-1、runs/round-2 分别保留模型实际输出；独立评测不继承父对话。
- revision/ 保存实质返工输入、副本、新旧版本、问题、包与执行日志。
- 先提交范围与验收标准；再提交工程修复及测试；最后提交实际验收产物、评分和最终状态。
