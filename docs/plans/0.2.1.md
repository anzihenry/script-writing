# 0.2.1 优化计划

状态：M0–M4 实现及本地验证已完成并按阶段提交；M5 待完成。远端 CI 与发布尚未执行，详见[本地验收](../validation/v0.2.1/README.md)。下文保留原计划及验收要求。
日期：2026-10-30。基线：v0.2.0 / `30e7393`。

## 1. 目标与范围

提高连续性引用和交付包核验的可信度，降低多集检查的重复开销，并将确定性回归纳入持续集成。继续使用 Python 标准库、本地文件和单写入者模型，保留现有命令入口及 37 个 Skill 的职责。

暂定以 0.2.1 交付；VERSION 和 CHANGELOG 到发布验收时更新。项目及交接协议维持 1.0，新增可选字段须由旧项目兼容测试覆盖。不引入自动迁移、持久化检查缓存、Web UI、并发写入或模型调用框架。

## 4. M1：连续性证据定位

主要位置：`pipeline.py` 的 continuity_index、正文解析辅助函数；`tests/test_continuity.py`；结构化记录规范与连续性技能。

实施内容：

- 先盘点当前模板、示例、历史演练实际使用的 location 形式，明确支持的场次 ID、对白 ID，以及是否允许组合定位。拒绝不完整 ID、跨集 ID、歧义或重复定义。
- 在受支持正文中建立 ID 到对应内容范围的映射。场次引用仅在该场次的正文范围核验 quote；对白引用核验对应台词，不能靠其他场次出现相同文字通过。
- 区分 ID 的定义与普通提及；不能把注释、引用示例或结构化块外的任意子串作为定义。JSON 权威对白和可读表沿用现有单一来源规则；自由动作文字只在明确的场次范围内定位。
- 明确换行及转义的归一化规则，不用模糊匹配掩盖文字变化。
- 无效 ID 或受支持格式下的错引作为输入错误；合法引用但正文格式无法可靠定位时返回 UNVERIFIED，并列出具体记录和原因，不将其用于推导可信当前状态。
- 保持“定位与原文绑定有效”与“提取语义正确”的边界，不自动判断人物知情或动作含义。

验收用例：完整合法引用、`EP003-`、ID 前缀碰撞、错集、错场、相同台词出现在不同场次、重复定义、转义文字，以及旧格式无法定位。正常对照和错误注入均覆盖 states 与 foreshadows。现有示例若需新格式适配，新增版本化示例，保留历史文件与哈希。

## 5. M2：交付包完整性

主要位置：`pipeline.py` 的 bundle、receipt、validate_extensions；`tests/test_delivery.py`；操作手册。

拟增加只读命令：

```bash
python3 skills/ai-short-drama-writing/scripts/pipeline.py verify-package PROJECT --id PACKAGE_ID
python3 skills/ai-short-drama-writing/scripts/pipeline.py verify-package PROJECT --id PACKAGE_ID --file /path/to/moved.zip
```

实施内容：

- 以 delivery 保存的 SHA-256 核验实际包，返回 VERIFIED / MISMATCH / UNVERIFIED；缺失或不可读为未验证并附原因，未知包 ID 或非法参数为输入错误。退出码分别为 0 / 1 / 1，输入错误为 2。
- `--file` 用于核验移动后的候选包，只读检查，不自动修改原路径、包 ID、哈希或来源快照。
- receipt 继续登记用户提供的实际接收依据；同时返回独立的包核验结果。登记 accepted 时若发现本地包明确不匹配则拒绝写入；本地包缺失时仍可登记有依据的外部接收事实，但完整性必须标为 UNVERIFIED。
- pending / returned 不因损坏而无法登记，避免阻断对损坏包的退回记录。任何接收状态都不自动意味着包已验证。
- 如保存核验信息，仅增加可选字段，记录核验时间、路径及实际哈希；它表示当时的观察，不能替代下一次实时核验。保留 events 前后快照和保存失败回滚。
- 基于已登记的完整 ZIP 哈希建立本轮核验，不额外扩展为通用 ZIP 解包工具。

验收用例：原包通过、字节损坏、错误候选包、文件丢失、包移动后匹配、不可读文件、未知 ID、旧 delivery 缺少核验字段、损坏包拒绝 accepted 且清单不变、缺失包接收明确未验证、损坏包可登记 returned。查询前后 project.json 和产物字节保持一致。

## 6. M3：检查性能

主要位置：inspect、gate、next_steps、status 分支，以及确有重复读取的 bundle 路径。

实施内容：

- 建立仅存活于一次命令的检查上下文，包含 manifest、kind/scope 查找表、按产物分组的历史及文件核验结果。
- next/status 共用一次 inspect 结果；gate 可消费该结果，直接调用 gate 时仍会自行检查。
- 同一次检查内按规范化路径复用文件哈希，包含重复引用的历史锁定基线；保留依赖闭包、循环检测、失效传播及错误顺序。
- 不跨命令缓存，不用 mtime 替代内容哈希；写操作之后丢弃旧上下文。bundle 的关键读取不能因缓存而扩大文件变更漏检风险，保持单写入者边界。
- 暂不大规模拆分 1,245 行脚本；只提取本轮复用所需的小函数或上下文，避免把性能修复变成架构重写。

验收：

- 三集示例 next 的完整检查从 13 次降至 1 次；在无额外历史文件的基线中，19 个唯一产物文件各读取计算哈希一次，总计 19 次。
- 在临时目录生成 3 / 30 / 100 集有效依赖链，记录 next/status 的检查次数、哈希次数和耗时。硬门槛采用次数及结果一致性，耗时只作对比，避免机器差异导致 CI 抖动。
- 修改文件后再次执行命令必须立即报告失效；缺文件、循环依赖、跨集影响、锁定历史篡改和检查点变化的诊断保持正确。
- 不宣称整个算法已达到线性复杂度；关口闭包和诊断输出仍可能随依赖规模增长，测量后再决定是否继续优化。

- 增加 GitHub Actions，在 push / pull_request 执行标准库 unittest；基线至少覆盖 Python 3.9 与实施时选定的当前稳定 Python，另在 macOS 运行一组路径与文件行为回归。
- CI 使用只读仓库权限，不需要密钥、模型服务或自动发布。Skill 元数据和本地链接继续由现有测试验证；官方 Skill 校验仅在明确取得校验器及依赖时单独记录，不把本地检查冒称官方验证。
- 执行单集旧例、三集新例的 check / next / index / parity，以及临时副本上的 bundle / verify-package / receipt 演练；记录预期的 UNVERIFIED，不要求旧格式伪装成全部通过。
- 同步 README、操作手册、结构化记录规范和直接受影响的 Skill 文案；更新 CLI 帮助及退出码说明。
- 在 `docs/validation/` 新建本轮报告，保存测试环境、结果、规模测量、兼容变化及限制，不修改 v0.2.0 的历史验收结论。
- 既有 52 项测试保持通过或有明确契约变更说明，新增边界用例通过；不以测试数量本身作为完成指标。
- 远端 CI 通过与本地测试通过分别报告。完成验收后再更新发布版本；本计划不包含自动推送、打标签或发布。

## 8. M5：技能评测扩展

新增至少 12 个案例，分为六组错误/正常对照：长距离知情依赖、道具多次流转、闪回与当前时间、角色谎言与事实、伏笔延期与漏收、相似台词的证据错引。部分案例采用 6–12 集文本，验证跨集定位能力。

先冻结输入、预置问题、允许推断范围和评分规则，再执行两轮隔离上下文评测；执行者不读取答案或另一轮结果。保留原始输出，逐项记录检出、误报、遗漏、证据引用和额外发现。额外发现单独裁定，不修改原分母。

目标为每轮预置重大问题全部检出、正常对照无重大误报、引用证据无伪造；未达到时如实记录并形成下一轮技能修订任务，不能靠修改答案或隐藏失败达标。该目标仅用于有界样本，不代表任意剧本的稳定准确率。评测执行方式在实施时选定；本计划不启动子代理或外部服务。
