# 0.2.1 可靠性契约

基线：30e7393；2026-10-30。实施顺序见 [计划](../plans/0.2.1.md)。

## 连续性引用

location 为单个完整 `EPddd-SCddd` 或 `EPddd-Dddd`（数字至少三位）。暂不接受组合定位或动作块 ID；动作通过所属场次定位。非法 ID、错集、受支持正文中的不存在 ID 或错引返回输入错误（退出码 2）。

支持的定义来源：script-json 的 scenes/dialogue；drama-table:v1 的场次标题及对白表。JSON 正文外的既有动作表可通过首列完整 `EPddd-SCddd-Bddd` 将动作绑定到已定义场次，不能将普通提及当定义。可读表的场次范围截至下一场次或同级/更高标题，代码围栏及注释不作为动作证据。

quote 仅在定位对应的台词或场次内容中匹配，保持文字、标点和空格，允许 CRLF→LF 和可读表的 `\|` 解码。JSON 字符串先解码。重复定义、双重权威来源拒绝。无法可靠定位的旧散文返回 UNVERIFIED，不推导可信当前状态；不自动改写历史示例。定位有效仍不代表语义提取正确。

## 包核验

`verify-package PROJECT --id ID [--file PATH]` 只读核验登记的整个 ZIP 哈希。VERIFIED=0；MISMATCH=1；文件缺失或不可读 UNVERIFIED=1；非法参数或未知 ID=2。结果包含包 ID、检查时间、实际路径、期望/实际哈希及原因。候选路径不修改交付记录。

receipt 保存可选 integrity 字段和事件快照，表示该次核验观察，后续查询不沿用该结果作为当前证明。accepted 遇到明确 MISMATCH 拒绝且无写入；包不可用仍可登记有依据的外部接收，完整性为 UNVERIFIED。pending/returned 不因包损坏而被阻止。接收证据真实性仍由调用者负责。

旧项目没有 integrity 字段仍可读取；新字段在存在时校验结构。schema_version 保持 1.0，不自动刷新旧哈希或迁移文件。

## 检查复用

仅在同一次命令、同一 manifest/文件读取阶段复用 inspect 和哈希。next/status 共用一次全量检查；直接 gate 默认重新检查。每次新命令重新读文件；写入后不得复用旧检查。保持错误排序、依赖传播、历史锁定保护和只读性。

## M0 基线结果

原有 52 项测试通过。新增三个回归目标在基线为 expectedFailure：不完整 location、损坏包 accepted、next 重复扫描。对应修复完成时移除 expectedFailure；发布时不能残留这三个预期失败。三集基线实测为 13 次 inspect / 247 次 sha，目标为 1 / 19。
