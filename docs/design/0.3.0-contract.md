# 0.3.0 实施契约

日期：2026-11-05。状态：M0 契约；实验与任务包实现后更新实际边界。

## 历史与当前输入

历史输入位于 `docs/validation/v0.3.0/archive/v0.2.1/files/<原路径>`，旁附 manifest，逐文件记录原路径、原 freeze 哈希、来源提交。归档只接受与旧 freeze 相符的字节。历史输出与评分仍引用原位置，原 freeze 不变。历史准备器默认读取此快照，继续支持原 `--round 1|2 --output PATH`。

当前准备入口使用 `--mode current --cases PATH --rule PATH ... --output PATH`；显式选择任务实际所需规则，验证本地 Markdown 传递依赖并打包，不能携带 oracle 或其他运行结果。当前案例不得指定 oracle，数据集应含 cases 数组与唯一 case_id。所有依赖须位于仓库 skills/ 内，不读取越界链接。当前包 manifest 记录模式、提交（含 dirty 标记）、输入文件哈希、案例顺序与来源路径。文件哈希是实际内容身份，提交号不单独证明工作区输入。

历史与当前包都拒绝覆盖目标，先在临时目录完成校验再原子改名。准备器不运行模型。成功退出 0；输入或文件错误退出 2，失败不留部分目标。当前新 manifest 的 schema_version 为独立的 1，不修改 project.json 协议版本。

输出校验函数接受显式 cases_path，CLI 增加 `--cases`；默认数据集维持旧调用行为。历史评分测试显式使用归档 cases。定位校验不等于语义评分。

## 实验记录（M2 冻结前草案）

实验数据：24 个任务，六类各四个；开发/保留各十二个，同源变体不得跨组。至少四个任务包含十二集完整分场文本。开发 A/B/C × 两轮，保留基线/候选 × 两轮；试运行独立存放。

每次 run manifest 包含 run_id、task_id、split、condition、replicate、input_hashes、rules_hashes、model（未知为 null）、执行预算、宿主上下文限制、开始/结束时间、实际执行者及工具能力、结果状态、output_hashes。attempt 单独编号，重试不覆盖旧结果。

状态分为 prepared、completed、task_failed、infrastructure_failed、not_run；prepared 不计为执行，not_run 不计成功或失败。评分绑定原始输出哈希，列逐项必达项、关键违规、引用定位、语义支持、额外发现和不确定性。评分展示匿名 run ID，条件映射单独保存。成本记录可取得的 token、耗时、读入字节、工具调用；未知值为 null。若宿主不暴露实际预算/用量，说明无法严格控制或测量，不编造数值。

同条件跨轮使用新上下文。开发运行按任务轮换 A/B/C 顺序，第二轮反序；不以内容修改或选择性重跑提高得分。任务硬约束与统一 CLI 帮助对三组相同。具体样本、rubric 和精简规则在试运行后冻结。

## 任务上下文包（M3 实现契约草案）

拟定 `context PROJECT --scope S --stage G --output PATH [--task TEXT]`，以及 `verify-context PROJECT --file PATH`。项目是只读来源，输出必须为项目外的新目录，防止覆盖或混入产物。参数错误/未知 scope/阶段范围不匹配退出 2；成功生成仍含阻塞项的包退出 1，完整生成退出 0。阻塞项不阻止用户查看诊断，不改变选择的阶段。

包内 `manifest.json` 包含 schema_version、scope、stage、用户 task（数据）、来源 project.json 哈希、sources（原路径/副本路径/产物 ID/版本/哈希）、rules、blockers、warnings、completion、authorization。`context.md` 提供阅读入口；sources/ 与 rules/ 保存可核验完整材料。摘要或索引包含原文定位并注明语义尚未推定。authorization 未提供时为 unspecified，不从 next 推断新的授权。

依赖选择复用 prerequisites/closure；目标缺失时仍提供已有前置；不能把已存在的目标产物排除在阅读材料之外。连续性只消费目标前集的实际状态，审核目标时可附本集台账；旧格式或 stale 明确未验证。规则按目标阶段选取，不一次加载全部技能。

verify-context 重新核对项目清单、来源、规则和包内副本哈希，不沿用旧检查缓存；匹配退出 0，内容变化/缺文件退出 1，非法包/路径退出 2。摘要不是权威状态，记录不表示已审核。两个命令不登记、不刷新依赖、不改变 issue 或产物状态。

M3 正式实现前根据 M2 恢复失败证据收敛字段；任何实质变更写明理由与对应测试。保持 next/check/gate 的旧接口与 project.json 1.0。

## 兼容与验收

历史证据完整性和当前示例兼容分开测试。v0.2.0 演练保存的源码副本与包保持原字节，当前 return-season 另由运行演练验证，不用历史字节等同要求阻止将来正常迭代。旧项目无需迁移，旧散文保留 UNVERIFIED。

CI 仅检查确定性行为、归档绑定和协议结构。新语义结论必须来自对应候选的实际执行；没有 M2/M3 结果不声称 M4 效果改进。此契约不批准发布或真实制作接收。
