# 0.2.0 数据契约与验收设计

状态：实施基线；2026-10-25。需求编号见 ../plans/0.2.0.md。

## 兼容策略

project.json 和交接 JSON 的 schema_version 保持 1.0。新增管理字段为可选数组 `events`、`checkpoints`、`feedback`、`deliveries`、`measurements`；缺省等于空数组，只有实际操作才写入。不重写旧正文、不刷新旧哈希、不迁移审核结论。旧项目可直接 check/status/next；新能力没有结构化输入时返回 UNVERIFIED。扩展不支持旧版 CLI 的新命令，升级工具后再使用。

结构化创作数据嵌在所属 Markdown 的唯一 fenced block 中，语言标签分别为 `continuity-json`、`outline-json`、`script-json`、`handoff-json`、`review-json`。它们随原产物登记、哈希与依赖一同失效，不另建无版本的侧表。script-json 是采用新模板时的权威对白/场次/资产清单，散文动作仍可自由编写；旧格式不猜测解析。

## 字段与唯一来源

| 记录 | 最小字段/约束 | 存储 |
| --- | --- | --- |
| 问题 | 沿用 id/scope/severity/status/location/summary/affects/evidence/verified_revisions；接受例外增加 actor | project.json issues |
| 管理事件 | at/type/id/before/after/note；追加、不覆盖 | project.json events |
| 检查点 | id/at/scopes/snapshots/open_issues/next_entry/reread；snapshot 为产物 ID→完整登记条目 | project.json checkpoints |
| 实际连续性 | states:[object,field,before,after,location,quote,temporal]；temporal=current/flashback；foreshadows:[id,status,location,quote,reason] | continuity Markdown，来源为其 script 依赖 |
| 伏笔计划 | foreshadows:[id,plant,payoff]，引用已登记集 ID | outline Markdown |
| 对白/场次 | scenes:[id,location_id,character_ids,prop_ids,dialogue:[id,speaker_id,text]] | script/handoff Markdown |
| 范围审核 | episodes/method/dimensions，维度包含 status/evidence；来源快照由登记管理 | project 范围 season_review 产物 |
| 反馈 | id/package_id/source/location/evidence/layer/issues/status/verification | project.json feedback |
| 交付 | id/scope/at/files/sha256/path/supersedes/status/evidence/parity | project.json deliveries |
| 实测 | id/package_id/seconds/source/evidence/at | project.json measurements |

状态字段是离散事实维度，例如 `CHAR001 / knows_page`，不能把所有知情信息写成不可比对的长段文字。before=null 表示此前未记录，不代表此前没有这个事实。每条变化必须附正文中实际存在的 location 和 quote；检查只能证明引用存在，不能证明提取语义正确。按集序及数组顺序处理；flashback 只进入历史，不覆盖当前状态。发现 before 与上次 after 冲突则保留冲突，不自动消解。

索引按需从当前有效输入重建，不持久化另一份事实源。覆盖缺失/失效的集时，结果不得为 VERIFIED。范围审核新增 kind=season_review/scope=project，依赖当前全部 script/continuity；全季未完成时可输出范围报告草稿，但不能把它登记成全季通过。

## 命令契约

- `episodes PROJECT --through N`：只追加，目标总集数幂等；预检全部目标路径，冲突拒绝且不覆盖。
- `issue PROJECT add/list/resolve/reopen/accept ...`：状态变更验证后原子写入；关闭需证据；accept 需 actor，P0 拒绝。
- `next PROJECT --scope EPxxx|project [--json]`：只读，按项目阶段和前置集顺序返回阻塞、技能和输入。scope=project 覆盖全部集。
- `checkpoint PROJECT --id ID --scopes EP001 EP002 --next-entry TEXT --reread TEXT`：保存快照；next 重新检查，不相信旧快照。
- `index PROJECT --through EPxxx [--object ID]`：输出状态历史、冲突、伏笔和未验证项。
- `impact PROJECT --id ARTIFACT`：只读，依赖拓扑下的直接/间接受影响列表，不自动解除失效。
- `feedback PROJECT add/update/list ...`：未识别包保留待分诊；关闭需回验证据及关联问题已处理。
- `parity PROJECT --scope EPxxx`：确定性比对，退出码 0=匹配、1=不匹配/未验证、2=输入错误。
- `bundle` 增加可选 --delivery-id/--supersedes；新交付记录必须绑定真实 ZIP 哈希；`receipt` 登记接收结果；`measure` 登记实测。

## 需求到验收

| 需求 | 正常对照 | 错误注入 |
| --- | --- | --- |
| R01 | EP001 追加至 EP003，重复执行无修改 | 目标文件冲突、非法总数、越界链接 |

## 三集案例与恢复示例

原 examples/return-demo 保留为 0.1.0 兼容样例。新增 examples/return-season：EP001 收到钥匙和纸片；EP002 错编号试探，来访者纠正，林夏确认其看过原页；EP003 保留证据联系管理处，对方索纸离去。F001 在 EP002 回收，F002 在 EP003 回收。钥匙始终在室内；确认“看过原页”不等于确认“偷窃者”。

恢复旧项目：复制 return-demo 到临时工作目录 → check → next → episodes --through 3 → 再次 next。旧文件与已登记哈希必须相同；新增集为空模板、没有获得阶段通过。旧 EP001 无新格式时 index/parity 显示 UNVERIFIED，不能写成失败的剧情结论。

实际编写新案例时在 EP001 后保存检查点；错误用例只在临时副本中注入；反馈演练明确 simulated，不声明真实下游接收。
