# 阶段技能共同约定

所有阶段入口与子技能开始时读取本文件，其余细节按各自入口读取。

- 用户现有约束、目录和格式优先；无指定时使用[模板](../assets/templates.md)布局。对话材料也是有效输入，不因缺少规定文件名而重复创建上游内容。
- 区分已确认事实、创作提案和缺失信息。未指定规格时可采用中文、单集 60–120 秒、先做一集样稿作为显式假设；总集数、受众、风格和预算不冒充已确认。不超出请求展开整季正文。
- 原创允许提出新设定；改编保留原文位置与新增/修改标记，未读材料不作为原作事实。只询问真正阻止任务完成的信息，同时推进不依赖它的工作。
- 阶段检查不是逐步审批。已授权范围连续完成；锁定和用户批准须记录实际依据，不编造确认或下游接收。
- ID 稳定且可追踪：角色 CHAR001、地点 LOC001、道具 PROP001、集 EP001、场 EP001-SC001、时间块 EP001-SC001-B001、对白 EP001-D001、伏笔 F001。插入和改名不重排旧 ID，删除 ID 不复用。
- draft 是工作稿；reviewed 需要明确审稿范围、方式和结果；locked 需要用户或指定负责人确认；superseded 保留追溯。完整规则见[流程](workflow.md)。锁定稿保留旧版，新修订不自动替代制作基线。
- 每次交付带阶段、输入来源/版本、输出路径/版本/状态、完成范围、检查结果、假设与未决项、下一阶段所需输入。局部任务不强制生成整套项目包。
- 各阶段仅复制[模板](../assets/templates.md)中所需部分。台词表与 JSON 是指定版本正文的派生结果；正文改变后同步更新，避免维护出矛盾版本。
- 题材、审美和作者表达优先于固定套路，不规定每几秒必须反转，不以评分预测商业表现。时长与制作能力未实测则标为估算或待验证。
- 本套技能止于剧本与制作交接，不自动生成视频、发布或联系他人。风险替代方案保留叙事作用，不静默删除关键情节。
- 自审与独立审稿如实区分；前文缺失只能审核当前材料，不能声称全季连续性通过。需要现状及工具能力时查[来源](sources.md)并核对当前官方资料。

共享依赖位于 `ai-short-drama-writing`。阶段技能可独立调用，但搬迁或安装时必须保留此目录及相邻路径；缺少文件时明确报告，不假定已读。

## 子技能协作与产物归属

- 明确的细项任务直接使用对应子技能；阶段综合任务使用阶段入口；跨阶段任务使用总入口。入口仅组合步骤，不复制另一套子技能执行逻辑。
- [子技能目录](subskills.md)列出全部职责。多个技能可维护同一项目文件的不同章节；不得相互覆盖不属于本次任务的内容。状态台账区分计划与实际。
- 子技能的完成只表示该产物检查通过，不自动将整集或整季提升为 reviewed。整体状态必须依据实际审核范围与结果。
- 创作类子技能修改其负责的内容；审计子技能只写问题报告；修订技能根据请求改稿；交接子技能只提取指定版本。错误必须回到负责层修复，再刷新派生文件。
- 共用标识除人物/资产/集场外，可使用 REQ001（需求）、SRC001（素材）、NODE001（总纲节点）、RULE001（世界规则）、ARC001（阶段弧线）、Q001（审核问题）。在各自类型内唯一；已有项目标识优先，避免无谓改号。
- 变更后记录受影响文档/章节/版本及待复核原因。完成复核前，不把旧台词表、JSON 或旧审核结论标成适用于新稿。

## 接入项目控制

进入批量管线时，遵循[管线说明](pipeline.md)及[操作手册](operations.md)。存在 project.json 就在工作前检查版本与依赖；完成本次可交付范围后登记产物并运行相应关口。无需每写一段都登记版本，更不能只改哈希来消除过期提示。

计划伏笔与计划状态归 outline.md；实际状态归 continuity/<集>-<版本>.md。后集正文依赖前集实际状态，本集实际状态依赖本集正文；禁止形成反向依赖。

审核问题以 project.json 的 issues 记录机器状态，报告写详细证据；改稿前重新打开受影响的已关闭问题，复核后再绑定新版本关闭。所有原文、证据和批准真实性仍由执行者核实。

模板正文以 assets/project-template/ 的独立文件为唯一来源，templates.md 仅作导航。先完成当前内容再移除未填写标记，登记状态不等于内容已获批准。
