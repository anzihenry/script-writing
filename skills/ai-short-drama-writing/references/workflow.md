# 生产流程与变更控制

详细执行与项目状态见[生产管线](pipeline.md)，命令与数据契约见[操作手册](operations.md)。本文维护阶段职责、创作入口和返工原则，避免重复定义机器字段。

## 上下游边界

选题/IP 与业务简报 → 故事开发 → 分集结构 → 单集剧本 → 剧本审核 → 分镜与资产规划 → 图像/视频/声音生产 → 剪辑审片 → 发布与反馈。

本技能套件负责故事开发到剧本交接。接收下游反馈并修订叙事相关问题。实际团队可让一人兼任多种职责；角色名表示责任，不强制组织架构，也不默认启动多个代理。

| 阶段 | 主要输入 | 输出 | 责任视角 | 通过条件/返工去向 |
| --- | --- | --- | --- | --- |
| G0 立项 | 创意或原文、受众、规格、制作约束 | 项目简报、假设与未决项 | 制片/策划 | 叙事承诺和范围可描述；规格缺失先用显式假设，原文缺失不能做忠实改编 |
| G1 故事设定 | 简报、可用素材 | 一句话故事、完整总纲、人物卡、世界规则、资产表 | 编剧/主编 | 主角目标、阻力、代价、结局闭环；改编保留项及修改项可追踪 |
| G2 分集 | 已有设定、规格 | 全季分集表、伏笔表 | 主编 | 每集带来新局面，结局有铺垫；不成立则回 G1/G2 |
| G3 单集 | 本集大纲、前集状态、资产表 | 分场剧本、时间预算、状态变化 | 编剧 | 可看见/听见，角色行为有因果，时长可容纳；问题回本场或 G2 |
| G4 审核 | 剧本及关联台账 | 定位问题、修订稿、复核结果 | 审稿/制片视角 | 没有阻断制作的问题，重大问题已修复；注明自审或独立审稿 |
| G5 交接 | reviewed 或 locked 版本 | 交接清单、台词表、资产需求、未决项 | 编剧向导演/美术/声音交付 | 下游能定位版本、场次、人物、状态和必要信息；未锁定稿注明仅供预制作 |

关口是检查点，不是每步等用户回复。用户明确要求试写时可以并行形成暂定设定与样稿，但不能把暂定设定标为已确认。只有缺失输入真正阻止目标完成，才等待对应输入。

## 阶段内执行

每个 G 阶段由五个子技能承接，详见[子技能目录](subskills.md)。阶段表继续定义整体关口；子技能只负责指定章节或派生产物，不自动代表整个阶段通过。共用同一版本与台账，返工时按问题定位选择最小子技能集合。

## 两条入口

**原创：** 先形成叙事承诺、人物关系与结局方向，再倒推因果链。用户只要一个短篇时可以将 G0–G2 合并成简短前言。

**改编：** 先记录来源章节/段落、可用范围、必须保留的关系与节点，再做“原文事件 → 剧中集/场 → 保留/合并/删减/新增 → 原因”映射。长篇材料分块提取并保留来源锚点，不能靠片段总结冒充全本阅读。授权状态只记录用户提供的事实，不据此自动阻断内部试写；商业交接时将未解决的权利事项列为制作方待确认项。

## 批量生产

1. 先形成整季结构，避免边写边无限追加设定；用户允许探索式写作时将结构标为暂定。
2. 首批选 1–3 集校准口吻和时长，这是建议，不是硬性集数。
3. 每批附“输入版本 + 本批摘要 + 连续性变化 + 未回收伏笔 + 下一集入口”。摘要不能替代有争议处的原文核查。
4. 读完本批相关原文和台账后写下一批；跨批检查人物知情范围、时间、承诺、物件和伤势。
5. 结尾批次检查主线承诺和关键伏笔是否兑现。开放式结局也要区分刻意留白与遗漏。

## 状态与版本

- `draft`：工作稿，允许尚未解决的假设。
- `reviewed`：已按标准自审或审稿；记录审稿者/方式、版本、日期与问题。通过审核不等于获准投入正式生产。
- `locked`：用户或项目指定负责人明确确认作为制作基线；记录确认依据。对话中已明确授权可作为依据，无需重复确认。
- `superseded`：被新基线替代，保留用于追溯。

版本采用 `v1.0`、`v1.1` 等，版本号不表达批准状态。建议设定/情节结构变更升主版本，措辞/局部修订升次版本；项目已有规则优先。已锁定稿不得覆盖丢失。相同资产、场次的 ID 不因排序而变化，删除 ID 不再用于新对象。

## 修改与返工

每次变更记录：请求/原因、旧版本、新版本、改动 ID、叙事变化、受影响集场/伏笔/台词/资产、需要下游重做的内容、状态。

| 反馈 | 优先处理层 | 复核范围 |
| --- | --- | --- |
| 角色无动机、反转无前提 | 人物设定/总纲/分集 | 因果链及所有依赖该前提的集 |
| 台词太长、解释重复 | 本场剧本 | 时长、必要信息、人物口吻 |
| 复杂动作难生成 | 分镜拆解；仍不成立再提议剧本替代 | 叙事功能、场末状态和下集连接 |
| 角色换脸/服饰漂移 | 美术参考与生成 | 只有剧本外观定义冲突才改剧本 |
| 前后持物、伤势、知情矛盾 | 剧本与连续性台账 | 首次变化点到相关后续场次 |

避免为一个镜头失败重写整季。反过来，不能只修当前台词而放过设定变更引起的后续矛盾。
